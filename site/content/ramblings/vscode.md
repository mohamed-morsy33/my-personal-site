title = "Why I use VSCode"
posted = 2026-11-22
+++

Even though I used to be a big advocate for using just the terminal for everything and avoiding my mouse, going so far as to use an extension in my browser ("vimium", I think it was called) that would allow me to do just that literally *everywhere*, I eventually realized I was burning out.

I spent more time configuring macros and adjusting things to "look cool" and "be more optimized", and I realized I wasn't actually focusing on what I cared about, which was just writing the code.

The tool doesn't really matter, especially when you actually have skill. While I agree being good at using certain tools can speed you up, being fast and trash at something isn't nearly as helpful as being fast and good at something.

I still do code in the terminal sometimes, and I use vim motions in almost every editor I use, but that's out of habit, not some superiority complex thing.

I highly recommend learning vim (I guess neovim now), since ever since I started using it I've been able to make quick changes in my code without doing the irritating thing of having to point, click, and drag.

End of the day, if you code in the terminal and that makes you feel cool, then go ahead. But when you use the terminal, don't just use it to "look cool", but have purpose in the tool you're using. In my case, VSCode worked for me since I've used it longest and I know more about its quirks and settings compared to coding with a custom configuration I hashed together that constantly needs updates and maintenance.

I don't know where I heard this, but I think there's a quote that goes something like "it's not the tools that make a builder".
